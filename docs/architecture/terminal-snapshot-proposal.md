# 完整终端恢复：实施阻塞与方案取舍

状态：待确认；不改变 ADR-001，不引入 vendor 或终端 fork。

## 已有证据

`mise run probe-snapshot` 对比「原始 Rust terminal 处理 prefix」与「新 terminal 处理视口 replay」，再给双方相同 suffix 和查询。9 组初始画面均相同，只有普通文本继续一致；其余 8 组失败。报告为 `target/probes/snapshot.json`，命令退出非零。

失败覆盖 pending wrap、非活动主屏、保存光标、滚动区、insert mode、活动字符集、未完成 CSI 和 UTF-8。这是现有有限 replay 的失败，不代表已经尝试并证明所有 VT 序列恢复方案不可能。暴露状态也不保证立即解决所有恢复问题；仍需跨解析器模式与续流测试。

源码核查：alacritty_terminal 0.26.0 的 inactive_grid、active_charset、tabs、scroll_region 等状态是私有字段。公开 active grid、mode、colors 足以检查部分状态，但不足以直接导出全部恢复所需状态。切换真实终端缓冲区以窥视 inactive grid 会扰动状态，不采用这种办法。VTE 的未完成输入还要独立解决，不能仅增加 Term getters 就宣布通过。

## 选项

### A. 许可验证最小、只读状态访问补丁（建议）

保留 Rust 权威 + xterm disposable display；先验证 feature-gated 只读 getters/state view，再在本项目实现恢复序列和有界未完成输入处理。精确锁定补丁基线、保留许可证、记录与上游 diff，争取上游合入。先做验证，不承诺一定成功，也不批准无界历史/原始会话录制作为替代。

代价：开始承担一个终端解析器补丁的升级和回归维护；这是核心依赖维护政策变化，故请求确认。与此前撤销的 GTK proc-macro 补丁无关，后者继续保持原状；不调整既有安全/许可证门禁。

### B. 不维护补丁，先评估其它 Rust 解析器

触发计划中的 S2 备选调查，比较 vt100 等已发布库的非活动屏/模式/字符集/增量输入状态可访问性、恢复正确性、内存与协议兼容性。只有证据足够才更改 ADR-001。更换解析器不自动解决与 xterm 的差异；可能仍需额外适配或发现也缺少公开状态。

### C. 重新设计前端恢复/渲染边界

保留 Rust 权威，改为后端格子快照/差分、前端只渲染，避免新前端解析器重建隐藏模式。xterm 没有已验证的公开任意格子导入方案，不使用私有 buffer 注入冒充稳定接口。需要评估自己的 renderer 或其它渲染器，并重做 IME、选择、可访问性、字体、性能及快照协议，是更大架构变动。

## 不做的绕过

- 不把视口相同算作恢复通过，不丢弃失败用例。
- 不为了躲门禁保留所有隐藏 xterm 实例，或把权威状态搬回前端。
- 不无界保存原始输出以全量重放；这违背内存、生命周期与数据安全目标。

确认前可以继续不依赖 attach 的基础工作，但生产 detach/attach 与落后恢复不可接入有限 replay。
