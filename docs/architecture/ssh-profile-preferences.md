# SSH配置与默认身份

每个当前保存的SSH入口对应一个独立SSH Profile。机器名称、入口名称和配置名称分别保存；配置编辑修改名称、登录用户名和默认Identity引用。默认引用支持现有密码和私钥目录，只保存ID，不读取或产生凭据。多个入口可引用同一个身份；同一入口的多个Profile及其他协议尚未开放。

`pulse-store::ssh_profiles` 在共享SQL worker的同一个事务中捕获完整HostSnapshot与两类Identity元数据，包括修订、内容和墓碑。编辑仅接受该来源中的Profile；外来owner、旧入口、同修订内容替换、身份改变／删除和未知或跨种类同号的身份均拒绝。旧Host投射及独立图在同一事务中更新，最终授权检查失败时整体回滚。旧目录用户名作为兼容投射同步更新，配置名称与默认引用不改机器或端点值；一次保存推进一次目录修订。凭据激活仍是上层独立的Vault授权边界。

`workspace_ssh_profiles` 与 `workspace_ssh_profile_save` 使用原窗口／原页面nonce、MetadataScope和单次五分钟捕获票据。读取和写入沿用原Metadata I/O执行额度与退出屏障。页面关闭／导航清理捕获，表单取消隔离晚结果；等待取消不承诺撤销已提交的保存，不自动重试不确定结果。旧库只读不迁移，用户应先在主机管理页明确启用多入口管理。

主机目录v3在同一来源里附带Profile的ID、名称和默认身份；v1/v2输入保持读取兼容。连接表单将保存主机与该默认身份预选，匹配当前可用的身份种类和用户名。未设置、已删、未配置凭据、用户名不符或跨种类同号的默认值均要求用户重新选择，不改选第一身份。用户可手动改选，随后仍走原密码／私钥的prepare、实际peer指纹、原epoch身份／目标批准及根会话启动流程。默认引用本身不授予Vault读取、签名或SSH连接权限，CLI仍要求明确的保存主机和身份ID。

入口为侧栏“SSH 配置”。表单精确解码有界元数据、使用文本节点显示外部名称、拒绝旧目标DOM提交；保存结果同步主机投射。当前主机和身份的可访问说明取自实际DOM选择，关闭时清空。

三项SQL/worker反例和原Host撤权检查、协议／旧DOM／晚结果／默认预选反例、TypeScript与workspace-ssh组合Clippy通过。公开 `mise run probe-workspace-ssh-profiles` 和Linux CI验证一次元数据流程：取消前保存零写、独立配置名称和默认身份一次提交、机器／端点／旧入口值及凭据／trust／组织内容不变、原连接表单默认预选后取消、公开刷新、独立进程重开、两次正常退出，未执行认证或写recent。初次哈希范围误包含允许修改的Host目录和Profile图，原失败截图与日志保留；修正后仍逐字段比较完整机器、端点与旧入口内容。
