# 负载结束后的可见屏幕状态比较

本工作包已在Linux Xvfb／软件渲染的独立release验证构建中，核对真实1GiB输出结束后的原始可见屏幕。夹具保留负载尾部，在最终标记前不清屏、不Home、不刷新；随后由真实按键请求有序Marker，绘制回调提交精确边界与摘要，后端返回Equal。该证据不扩大为隐藏解析器或全部历史一致性。

`TerminalViewBinding::request_marker` 只请求原页、原会话与原代际上的有序Marker。返回值仅代表准入；修订号、原始／UTF-8字节和几何必须来自现有流的Marker绘制回调，不能由Data长度推算。`compare_visible` 使用同一绑定，在请求前及回执后检查页面仍有效，沿用现有每会话500ms额度、250msActor查询期限与代际复核。两个接口均只读，不产生PTY输入、不清除风险位、不创建会话、不重新捕获页面权限。

共享可见摘要覆盖整个终端网格的字符、宽度、前景／背景、粗体／斜体／下划线／反色、光标与主／备用屏标记。这不是密码学认证，也不证明隐藏解析器模式、完整历史或所有VT状态一致。初始Commit确认继续专用于捕获图像，不改成最新状态证书。

应用层19项终端绑定回归、50项相关前端回归、2项原生元数据单测，以及App／生产／验证构建严格Clippy通过。独立`workspace-load-state-probe`构建只注册两个只读命令；专用前端资产以当前终端的真实Ctrl+Shift+F8请求Marker，并仅在绘制该Marker后提交比较。普通前端产物已核对不含验证命令，普通原生命令表不注册它们。正式任务`mise run probe-workspace-load-state`接入Linux负载CI。
