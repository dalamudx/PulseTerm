# 终端可视响铃

TERM-12 首批交付为当前挂载窗格的可视 BEL 提示。xterm 公共 `onBell` 事件触发固定文案“终端响铃 · 清除”，不播放声音、不申请系统通知权限。

- 每个 Surface 最多保留一个提示。重复 BEL 合并，不累积计数、定时器或通知队列，也不将远端文字作为通知内容。
- 只有原页当前视图在 Commit 确认后解析实时 Data 时才放行提示。解析期间还必须持有未取消的输出信号；恢复快照、屏幕修复和 EOF 解码不获得这项标记。
- 清除按钮只隐藏本地提示；若按钮持有焦点，则尝试返回当前终端的显示焦点，不启用 stdin 或提交输入。新 BEL 可再次显示提示。
- 视图释放时移除事件监听、提示节点与本次添加的定位类。撤销、尺寸暂停和旧视图的迟到解析不能新增提示。自然 EOF 已显示的提示可留在仍挂载的结束视图中，直到清除或释放。
- 不增加后端接口、输出订阅或 ACK。隐藏／暂停视图、未挂载标签和其他窗口不会为接收响铃而重新挂载。

提示样式沿用现有 UI 色彩 token 和 nonce CSP；不写入行内样式，不改写终端内容、字符宽度或解析器状态。

## 直接验证

本轮只执行三份受影响的 Vitest 文件，共 25 项行为，覆盖实时／回放、Commit 与修复隔离、取消与释放、输出滚动兼容；TypeScript、局部 Biome 和前端产品构建通过。Biome 保留已有 CSS 特异性警告。

Chrome 使用真实 xterm 和 Surface，确认 2,000 次 BEL 合并为单一提示、两个窗格隔离、清除及显示焦点恢复、回放静默、撤销清理、720px 布局及 stdin 持续禁用且零输入事件。它没有原生 IPC、PTY 或 SSH，不计原生 WebView 验收。TypeScript 语言服务不可用，未计入通过，也未安装额外工具。

沿用现有 CI 的前端单测、类型与构建，不新增重型矩阵。系统通知、声音、后台未挂载终端的响铃接收、原生 PTY／SSH 与 WebView、辅助技术实测及跨平台效果尚未完成。
