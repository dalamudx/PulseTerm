## 2. 推进顺序

主线：**Windows 普通用户生产存储 → 本地 Shell／ConPTY → 完整产品测量与优化 → SSH／CLI 和 macOS 补齐 → 跨平台稳定性 → Alpha 交付**。

资源准备、合规和可独立开展的 macOS 工作从第一阶段并行开始。后续工作包不必等待无关阻塞，但对外完成标记必须满足各自退出条件。

| 顺序 | 工作包 | 交付结果 | 退出条件 |
|---|---|---|---|
| A | Windows 生产存储与启动基础 | 接通实际设置、Profile、数据库、Shell 发现及 ConPTY 的最小产品路径；准备 Windows 原生构建／实窗验证通路 | 同一普通账户首次启动→发现／保存 Profile→明确批准→真实 Shell 输入／尺寸→刷新→重开配置→物理退出完整通过；不使用默认值或任意 exe 绕过未接通接口 |
| B | 完整产品性能与恢复 | Windows 和 Linux 使用真实产品、真实 PTY 的可复现 release 基线，完成有证据的优化；测恢复首屏／可输入／完整历史 | 本地回显、内存、冷启动及大输出达到适用门槛；完整原始样本、环境、尾部及失败保留，不能以页面或 headless 结果代替 |
| C | 跨平台 SSH／CLI 与 macOS | 将已有 Linux 主链接到 Windows／macOS；macOS 本地链与窗口生命周期可使用 | 已有认证方法、原页面批准、跳板、取消、CLI 冷暖入口、刷新及实际资源退出经过真实平台验证；外部互通与受限能力单独标注 |
| D | 系统交互与稳定性 | 收敛 IME、DPI、剪贴板、焦点、恢复及关闭故障，形成跨平台日常使用矩阵 | 无候选泄漏／重复提交；多屏缩放不破坏格子／输入；关闭与取消等待实际 native 回收；历史崩溃有明确状态，未复现不冒充修复 |
| E | Alpha 安装与发布 | 三平台可安装、升级、卸载并用于日常工作，文档和故障回传齐备 | 全部 P0 按原完成标准闭合，合规与签名／公证／更新通过，连续至少一周日常使用无遗留 P0 级缺陷 |

### A：先交付真实可用的 Windows 本地链

1. 接入既有平台安全原语及设置适配候选，覆盖正常保存、重开、损坏／未来版本拒绝、冲突、撤销和不确定提交。保持平台 I/O、存储逻辑与应用授权的分层。
2. 为 Profile／Vault／SQLite 单独验证所有者、ACL、链接、WAL／SHM、并发、迁移与工作线程退出。原子替换普通文件的通过结果不能直接当作数据库方案。
3. 补后端发现及保存的 Windows Shell／WSL Profile、参数／目录／环境、新窗口环境刷新和 ConPTY；每种入口均走原授权链。WSL 的字节、尺寸和生命周期另作实际验证，不等同于启动一个 Windows exe。
4. 接通 GUI 标签／分屏与会话状态，检查原页面输入、resize、刷新及 Root／native 退出屏障；IPC 和单实例中阻塞产品启动的部分同时补齐，完整 CLI 使用链在 C 阶段集中验证。
5. 以普通用户产品使用链验收。需要特权的链接夹具单独记录，不自动提权或改系统策略；本轮管理员 39/39 的原始范围保留。

这一阶段优先形成可用产品构建和成组验收，不再把每个设置开关拆成一次完整实机回归。Windows MSVC／SDK／WebView2 构建资源尽早落实；Linux 交叉编译不能替代该通路。

### B：先测清瓶颈，再逐项优化

测量对象固定为实际产品的 release 构建，区分本地 PTY 与 SSH，记录硬件、刷新率、缩放、Runtime、窗口大小及渲染模式。先定义全进程树和共享内存口径，不跨口径混算内存。

- **回显**：关联同一输入样本的发键、原生 PTY 写入、收到回显、后端处理／排队、IPC、xterm 处理及呈现。跨时钟先做可比较性和误差校验；逐样本保留原始时间点，不把各段 p95 相加。
- **呈现**：区分 xterm 写入回调、绘制事件和真实窗口像素变化；软件呈现测量不冒充物理按键到发光。诊断采样与正常性能运行分开，保留长尾及失败，不删除慢样本或放松门槛。
- **内存**：分别定位空窗固定成本、每会话增量、前后端重复历史及后台视图。优先评估后端分页＋前端短回滚，验证软换行、选区复制、查找定位和恢复；该优化不能解决全部空窗固定成本。
- **大输出**：继续验证 1GiB 输出、100ms 内 Ctrl+C、可见状态、续流及退出；保留之前通过和失败记录，限定各项正确性证据范围。
- **恢复**：分别记录首屏、可输入、历史完整加载三个时间，以及历史加载期间的输入延迟。先测量，再决定是否改变回填调度；保留快照切点、有界续流、查询应答所有权和输入确认。

| 指标 | 既定目标／判据 |
|---|---|
| 本地回显 | p95 <16ms；同时报告 p50／p99／最大值和完整样本 |
| 单标签空闲全进程内存 | <120MB |
| 20 标签（19 后台） | <250MB |
| 单会话十万行历史增量 | ≤20MB，并保留恢复／查找正确性 |
| 1GiB 文本输出 | UI 可交互，Ctrl+C <100ms，前后端内容符合既定一致性验收 |
| 冷启动到可输入 | Windows <700ms，M 系列 Mac <400ms；Linux 建立独立可复现基线 |
| SSH | 按固定 RTT／丢包／带宽场景单独报告；不把本地 <16ms 目标直接套到含网络往返的成绩 |

若空窗或最小真实页面仍超过固定内存预算，或者瓶颈来自平台呈现调度，产出受控 A/B 证据，再评审运行时／平台方案。任何目标或架构调整须明确评审，不静默抬高预算、移除权威解析或取消安全控制。

### C：复用成熟连接链，补平台与外部证据

- Windows／macOS 补齐实际 Profile／Vault 存取、SSH 适配、Agent 发现、IPC、CLI 冷暖窗口与异常退出。保持首次指纹核对、明确方法选择、原页／Vault 代际和取消后的物理排空。
- 当前 Windows 暖 CLI、固定同伴冷 CLI 与 SSH 配置导入已接线并完成对应共享回归／交叉检查；原生夹具不当作已执行。下一退出条件是普通用户真实平台链路和外部服务证据，不能将代码接线完成当作 C 阶段验收完成。
- 用已有密码／私钥／Agent 与 MFA 场景组织代表性组合，在真实平台和外部 SSH 服务端上验证；不因新平台重复所有未变化的 Linux 单元组合。
- 软件 RSA 继续显式阻断，先解决依赖安全问题再启用。未解决时不得把相应功能整体勾选完成；需要调整发布范围时单独评审。
- macOS 同时验证登录 Shell、启动环境、权限、Option／Meta、窗口生命周期及系统输入；没有原生资源时标明阻塞，先推进可独立的共享工作。

### D／E：稳定性与发行闭环

- Windows 普通用户、macOS、Linux 的真实 IME／CJK、DPI／多屏、字体、剪贴板、键盘焦点和辅助技术；受控缩放或合成事件不替代真实系统验收。
- 快照恢复、自然 EOF、刷新及关闭／取消中的原生任务退出；重点保留启动黑窗、历史 SIGSEGV、IBus 残留及候选位置问题的状态与可复现材料。
- 安装、升级／迁移／卸载、签名／公证、更新失败恢复、代理和中文英文帮助。验证构建不冒充可发布产品，实际发包受当前合规门禁约束。
- 日常使用反馈集中到有构建标识和环境信息的缺陷；按行为和影响排序，不以有限次数正常关闭宣称历史问题根治。

下面是后续依赖顺序，不缩减 v1.0 范围。P1 只有在直接阻塞 P0 主链时提前。

| 顺序 | 模块 | 主要交付 |
|---|---|---|
| 1 | SFTP／文件工作台（FILE-01～05）与网络（NET） | 复用 SSH／Route：双栏、队列、断点续传、编辑、目录跟随；本地／远程／动态转发及规则／状态 |
| 2 | Shell／SSH／工作区增强 | 各 Shell 自动集成、命令状态；SSH 复用须过 HOL 门槛，保活／重连／网络事件；跨窗口迁移、重启布局、广播输入及确认 |

| 4 | 其他 P1 与发行收口 | Telnet／串口、编码／日志及其他终端行为、Vault／应用锁／安全审批、加密备份导入导出、主题与系统集成、用户文档；按原功能表逐项闭合 |

## 5. Rex 资料的采用边界

[官方公测公告](https://www.superlogical.com/updates/public-testing-beginning)和[第三方介绍](https://www.bitdoze.com/superlogical-rex/)可启发会话与视图分离、实时流关键路径、分阶段恢复和 CLI 自动化。已有后端会话所有权不重做；增加上述测量并复核现有有序恢复即可。

两篇没有可复核的输入回显 p95／p99 原始成绩，“100 倍”I/O 论述不能折算为回显收益。公开客户端测试为 macOS，不能充当 Windows 验收。当前继续使用 Rust 权威状态＋前端终端渲染，不据文章直接切换 libghostty、移除后端解析、引入 Lua 或替换 SSH 身份／授权链。

## 6. 执行与进度回写

- 按完整使用链开发；每批做相关类型／编译、针对性测试和直接行为检查，若干相关能力就绪后集中原生验收。正常通过后不重复无变化全量矩阵。
- 每项状态分别记录：未接通、已接通待原生验收、指定环境通过、跨平台完成、发布可交付。失败、未覆盖条件和管理员／普通用户环境必须保留。
- 既有基础入口仍为 `mise run check`／`test`／`probe`／`audit`，各工作包使用对应专项；headless、交叉编译、零测试或语言服务 Unknown 均不能充当原生通过。验证结束退出任务并清理开发产物，保留 probes 证据。
- 每阶段以实际退出条件结束并更新主计划及验证记录；相关功能和常规修复连续推进，不做逐开关确认。只有真实阻塞或重大架构／范围决策才中断。
- 原三名全职工程师的日历排期不是当前承诺。本轮不虚构固定完工日期：原生构建资源、Windows 数据库适配、固定内存成本及安全依赖是主要不确定项；A 阶段形成可运行的产品构建后，再按实测重估后续工作量。
